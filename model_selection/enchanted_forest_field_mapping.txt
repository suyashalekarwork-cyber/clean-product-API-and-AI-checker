3. TWO PROBLEMS THIS PRODUCT EXPOSES
================================================================================

PROBLEM 1 -- extras: is mapped to the wrong field. (Real defect.)

  V4.4's LABEL MAPPING sends  extras:  ->  redo_desc_what_excluded

  That assumes "extras" means paid add-ons costing more. Here it means the
  opposite: a COMPLIMENTARY shuttle bus and free low-sensory accessibility
  sessions. Filing them under "what is NOT included" states the reverse of the
  truth -- a customer reading the output would conclude the shuttle costs extra.

  This is a PROMPT defect, not a model error. A model obeying V4.4 correctly
  produces this wrong result, because the mapping "overrides your own judgment".
  No model choice fixes it -- gpt-5.4-nano, gpt-5.5-pro and gpt-4o-mini would
  all misfile it the same way.

  Worth noting the accessibility content is now SPLIT: the wheelchair/pram line
  is in redo_desc_requirements (via accessibility:) while the low-sensory
  session detail is in redo_desc_what_excluded (via extras:). Same subject,
  two fields, one of them wrong.

  Possible fix for a future version: make extras: route on meaning rather than
  by fixed map -- "complimentary"/"free"/"included" -> what_included, an explicit
  surcharge -> what_excluded. Not built; flagging only.

PROBLEM 2 -- redo_desc_other holds two unrelated things.

  Pricing AND FAQs both land in redo_desc_other. Both are legal under V4.4
  (permitted kinds #1 and the faqs: -> other map), so this is not a rule
  violation. But it is why "FAQs split across fields" keeps recurring: the
  description side has NO dedicated FAQ field, while the booking side has
  redo_booking_faqs. Where FAQ content lands therefore depends on which side of
  the API it arrived on, not on what it is.

  Consequence here: the cancellation/refund policy inside FAQ #3 is real
  cancellation content, but it stays in redo_desc_other because the faqs: label
  governs the whole block. redo_desc_cancellation is left empty even though the
  product plainly has a refund policy.
