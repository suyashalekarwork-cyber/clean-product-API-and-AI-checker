------------------------------------------------------------
A CONTENT_LOSS finding
------------------------------------------------------------
  1. Find the "evidence" text in the RAW. Not there as quoted -> REJECT.
  2. Search EVERY column, including about, for that text or a normalised form
     (case, punctuation, bullet markers and whitespace do not count).
     PRESENT ANYWHERE -> REJECT.
  3. REJECT if it is any of: a lead-in ending ":" or ";" whose content
     survived; a section heading that only names the section beneath it; an
     inline "Label: value" whose value survived; a sentence-split artifact on
     "Approx." / "No." / "Mins." / "St." / "hrs."; a markdown link, URL or
     booking call-to-action; a greeting or sign-off; a standalone company name
     or licence number; a question used as a section heading.
     The OPENING tagline of a description is NOT a droppable brand fragment --
     it is content, and losing it is a real finding.
  4. Otherwise UPHOLD.

------------------------------------------------------------
A LABEL_LOSS finding
------------------------------------------------------------
FIRST, THE GATING QUESTION: WHAT FOLLOWS THE LABEL IN THE RAW?

  (c) A PROSE BLOCK -- one or more full sentences of description?
      -> **REJECT.** It is a section heading. Section headings are meant to be
      dropped, and the contract routes narrative ones to redo_desc_about with
      the label removed. It does not matter which column the prose landed in.
      Examples that MUST be rejected: "## The Skipper", "## The Boats",
      "##What You Will Experience", "##Special Note", "MEMBERS BENEFITS",
      "Boat details", "What's in the Speciality", "Tour Overview".

  (a) A VALUE -- a time, price, number, address, spec, name, short phrase? or
  (b) A LIST ITEM, or one entry in a run of similarly-labelled entries?
      -> continue below.

SECOND: **THE VALUE SURVIVING IS NOT GROUNDS FOR REJECTION. IT IS THE
DEFINITION OF THIS CLASS.** If you reject a LABEL_LOSS finding because "the
value is present in the column" or "a bare label is droppable", you have made
an error -- those grounds belong to CONTENT_LOSS.

  1. Find the label in the RAW. Not there -> REJECT.
  2. Confirm the label is ABSENT from every column. Present -> REJECT.
  3. Ask what the dropped label was doing:
       - A SECTION heading naming the column its content went to ("Duration"
         -> duration_text, "Inclusions:" -> what_included). The column name
         carries the meaning. -> REJECT, correctly dropped.
       - A SUB-ITEM label naming one item among several, or one entry in a run
         of parallel labelled entries ("Scenic Landscapes:", "Wetsuits:",
         "Departure times"). -> UPHOLD.
       - A label on values that are meaningless unattributed (bare times,
         bare prices). -> UPHOLD.
       - A QUALIFIER beyond the column's name -- which boat, which tier, which
         day, which customer type. -> UPHOLD.
       - The receiving column does name the concept ("Group Size:" ->
         redo_group_size). -> UPHOLD, severity minor.
  4. Otherwise UPHOLD.

------------------------------------------------------------
A MISCLASSIFICATION finding
------------------------------------------------------------
  1. REJECT if the remedy would move content OUT of redo_desc_about into
     another column. about is the contract's DEFAULT destination; text sitting
     there is correct by construction.
  2. REJECT if the supplier's heading is a reasonable synonym, a narrower
     instance, or an everyday phrasing of the column it went to. STEP 2 of the
     contract says headings need not match column names word for word.
     CORRECT placements: "Location" -> meeting_point, "Who is this for" ->
     restrictions, "Health Note" -> important_info, "Refreshments" ->
     what_included, "Tour Plan" -> itinerary.
  3. REJECT if the supplier's own heading is what put the content there -- that
     is at most a SUPPLIER finding. If the finding claims owner OURS on that
     basis, set owner_correction to "SUPPLIER".
  4. UPHOLD a difficulty or grading value sitting in redo_desc_restrictions
     ("Difficulty: Hard", "Moderate", "Advanced", "Grade 3"). Confirmed
     reproducible across two runs.
  5. Otherwise UPHOLD only when the supplier's heading plainly names a
     DIFFERENT column from the contract list.

------------------------------------------------------------
An EMPTY_BUT_HEADING finding
------------------------------------------------------------
  1. **REJECT if the heading's content is present in redo_desc_about.** That is
     the correct outcome of the contract's STEP 3 line tests -- a line under an
     Itinerary heading with no clock time or step number FAILS the test and
     moves to about, leaving itinerary legitimately empty. Nothing was lost.
  2. Locate the quoted supplier heading in the RAW. Not there -> REJECT.
  3. Confirm the named column really is empty. Filled -> REJECT.
  4. If the heading's content went to a different column and nothing was lost,
     this is at most a MISCLASSIFICATION -> REJECT.
  5. Otherwise UPHOLD.
